Solid modeling is the branch of CAD concerned with the representation, construction, manipulation and analysis of three-dimensional solid objects. A solid model is not merely a visual drawing of an object. It is a mathematically meaningful representation that can answer geometric and topological questions such as volume, surface area, inside–outside classification, intersection, adjacency, mass properties and manufacturability.

Key Idea

A solid model must represent a closed, bounded and physically meaningful three-dimensional object. It should be possible to distinguish the interior, boundary and exterior of the object.

Solid Modeling vs. Engineering Graphics

Engineering graphics and solid modeling are closely related, but they are not the same.

Engineering graphics is mainly concerned with representing three-dimensional objects using two-dimensional drawings. Orthographic views, sectional views, dimensioning, tolerances and projection methods are important in engineering graphics.

Solid modeling, on the other hand, represents the object itself in a computer. The model stores enough information to support operations such as sectioning, Boolean operations, mass-property calculation, meshing, tool-path generation and finite element analysis.

AspectEngineering GraphicsSolid Modeling
Main purposeCommunication through drawingsMathematical and computational representation of solids

Typical questionHow does the object look from a direction?What is the object, and how is it connected?

Remark

Engineering graphics is a language for communicating design intent. Solid modeling is a computational representation of the designed object. Modern CAD systems combine both: the user creates a solid model, and engineering drawings are generated from it.

Geometry vs. Topology

Main reference: Saxena and Sahay [1], Chapter 8. Further reading: Mäntylä [14] and Requicha [15] for solid representations and their topological foundations.

A solid model contains two different kinds of information: geometry and topology.

Geometry

Geometry describes the actual shape, size and position of entities. It answers questions such as:

  1. Where is a vertex located?

  2. What is the equation of an edge curve?

  3. What is the equation of a surface?

  4. What are the dimensions and coordinates of the object?

Examples of geometric data are:

\[ \mathbf P=(x,y,z), \]
\[ \mathbf r(u), \]
\[ \mathbf r(u,v), \]

and

\[ ax+by+cz+d=0. \]

Topology

Topology describes how geometric entities are connected. It answers questions such as:

  1. Which vertices form an edge?

  2. Which edges bound a face?

  3. Which faces meet at an edge?

  4. Which faces are adjacent to a given face?

  5. Is the object closed?

  6. Does the object contain holes or handles?

Topology is independent of exact dimensions. For example, a cube and a deformed cuboid have different geometry but the same topology.

Key Idea

Geometry tells us where things are. Topology tells us how things are connected.

Example

A square and a rectangle have different geometry because their dimensions are different. However, they have the same topology: four vertices, four edges and one face bounded by a closed loop.

Interior, Boundary and Exterior of a Solid

For a solid object \(S\subset \mathbb R^3\), every point in space belongs to one of three sets:

\[ \operatorname{int}(S), \qquad \partial S, \qquad \operatorname{ext}(S). \]

The interior of \(S\), denoted by \(\operatorname{int}(S)\), is the set of points that lie strictly inside the solid. Around every interior point, one can draw a small ball that lies completely inside the solid.

The boundary of \(S\), denoted by \(\partial S\), is the set of points that separate the inside from the outside. These are the points on the surface of the solid.

The exterior of \(S\), denoted by \(\operatorname{ext}(S)\), is the set of points that lie outside the solid.

Thus,

\[ \mathbb R^3 = \operatorname{int}(S) \cup \partial S \cup \operatorname{ext}(S). \]

Key Idea

A valid solid model must support inside–outside classification. Given a point \(\mathbf p\), the model should be able to determine whether

\[ \mathbf p\in\operatorname{int}(S), \qquad \mathbf p\in\partial S, \qquad \text{or} \qquad \mathbf p\in\operatorname{ext}(S). \]

Definition of Homeomorphism

Two objects are said to be homeomorphic if one can be continuously deformed into the other without cutting, tearing or gluing.

More formally, two topological spaces \(X\) and \(Y\) are homeomorphic if there exists a map

\[ f:X\rightarrow Y \]

such that:

  1. \(f\) is one-to-one,

  2. \(f\) is onto,

  3. \(f\) is continuous,

  4. \(f^{-1}\) is continuous.

If such a map exists, we write

\[ X\cong Y. \]

Key Idea

Homeomorphism captures the idea of topological equivalence. It ignores exact lengths and angles, but preserves connectivity and the number of holes.

Example

A sphere and a cube are homeomorphic because a cube can be continuously rounded into a sphere without cutting or gluing.

A sphere and a torus are not homeomorphic because a torus has a hole, while a sphere does not.

Euler Characteristic

The Euler characteristic is a topological invariant that relates the number of vertices, edges and faces of a polyhedral surface.

For a closed polyhedral surface,

\[ \boxed{ \chi=V-E+F } \]

where \(V\) is the number of vertices, \(E\) is the number of edges and \(F\) is the number of faces.

For a closed orientable surface of genus \(g\),

\[ \boxed{ \chi=2-2g. } \]

Therefore,

\[ \boxed{ V-E+F=2-2g. } \]

Example

For a cube,

\[ V=8,\qquad E=12,\qquad F=6. \]

Therefore,

\[ \chi=V-E+F=8-12+6=2. \]

Thus, the cube is topologically equivalent to a sphere, whose genus is \(g=0\).

Example

For a torus,

\[ g=1. \]

Hence,

\[ \chi=2-2g=2-2=0. \]

A torus has one handle.

Necessary, Not Sufficient

For a closed, connected, orientable polyhedral 2-manifold, the relation \(V-E+F=2-2g\) is a necessary topological consistency check. More general B-Reps with multiple shells, face loops or internal cavities require the corresponding extended Euler–Poincaré relation. Passing the applicable Euler check is not proof that a model is valid: incorrect adjacency can sometimes preserve the same global counts, and the equation does not test geometric conditions such as face–face self-intersection, overlapping faces, gaps, degeneracy or inconsistent surface geometry.

Interactive detour: work through the Euler-characteristic proofs for a triangulated square, sphere, and torus.

Euler–Poincaré Formula with Loops

A trimmed B-Rep face can have more than one boundary loop. Every face has one outer loop, while a hole in that face contributes an inner loop. Let \(L\) be the total number of face loops, \(S\) the number of connected closed shells, and \(G\) the sum of the genera of those shells. For a valid, orientable, manifold B-Rep boundary, the extended Euler–Poincaré relation is

\[ \boxed{V-E+F-(L-F)=2(S-G)} \]

Since \(L-F\) counts the inner loops, the same relation is often written as

\[ \boxed{V-E+2F-L=2(S-G).} \]

When every face has only its outer loop, \(L=F\). For one shell with no handles, \(S=1\) and \(G=0\), so the familiar formula \(V-E+F=2\) is recovered.

Concept of Genus

The genus of a closed orientable surface is the number of handles or through-holes in the object.

ObjectGenus \(g\)Euler Characteristic \(\chi=2-2g\)
Sphere-like object\(0\)\(2\)
Torus\(1\)\(0\)
Double torus\(2\)\(-2\)
Triple torus\(3\)\(-4\)

Key Idea

The genus is a topological quantity. Stretching or bending a solid does not change its genus. Cutting or creating a new through-hole changes its genus.

Solid Representations and Modeling Layers

A CAD system may combine several ways of representing or constructing a solid. These must be distinguished from the higher-level machinery that records design intent and rebuild dependencies.

Solid Representation and Construction Schemes

  1. Boundary Representation (B-Rep) stores the solid through its bounding faces, edges and vertices.

  2. Constructive Solid Geometry (CSG) stores a set-theoretic expression that combines solid primitives, usually in a Boolean tree.

  3. Sweep representation constructs a volume by moving a profile along a path or through a prescribed motion.

  4. Spatial decomposition represents occupied space using cells such as voxels, octree cells or other volumetric elements.

These schemes are not mutually exclusive. A system can evaluate a sweep or CSG expression and store the resulting body as a B-Rep, while using spatial decomposition for analysis, collision detection or manufacturing calculations.

Feature-Based Modeling: A History and Dependency Layer

Feature-based modeling is not normally a separate geometric representation at the same level as B-Rep or CSG. In mainstream parametric CAD, it is a history and dependency graph built above the geometric kernel. Its nodes record design operations such as sketches, extrusions, revolves, holes, fillets, patterns, datum features and Boolean features, together with their parameters and references.

During a rebuild, the CAD system evaluates this graph in dependency order. The nodes call geometric-kernel operations, and the current result is most often stored as one or more B-Rep bodies. A Boolean feature in the history may therefore invoke a B-Rep Boolean operation without making the entire feature history a CSG representation.

AspectCSG tree in the geometry layerParametric feature graph
Primary purposeRepresent a solid as a Boolean expressionRecord design intent, parameters and dependencies
Typical nodesPrimitive solids and union, intersection or differenceSketches, dimensions, extrusions, fillets, patterns, datums and Boolean features
Evaluation resultA regularized solid, often converted to B-Rep for downstream workA rebuilt model whose current bodies are usually B-Reps
Meaning of the tree or graphSet-theoretic construction of geometryOrdered and dependent history of design operations

Key Distinction

CSG belongs to the geometric representation or construction layer. Parametric features belong to the design-history layer and usually operate on B-Rep bodies through the kernel. Similar-looking trees do not make them the same model.

In these notes, the detailed geometric discussion focuses mainly on Boundary Representation and Constructive Solid Geometry.

Boundary Representation

Boundary Representation, usually abbreviated as B-Rep, represents a solid through its boundary. The boundary is made of faces, edges and vertices.

A B-Rep model stores both geometry and topology.

EntityMeaning
VertexA point in space
EdgeA curve segment joining two vertices
FaceA bounded portion of a surface
LoopA closed sequence of edges bounding a face
ShellA connected set of faces forming a closed boundary
SolidA region of space bounded by one or more shells

Key Idea

In B-Rep, a solid is represented by its boundary. The boundary must be closed, consistently oriented and topologically valid.

Advantages of B-Rep

  1. It represents complex freeform surfaces naturally.

  2. It supports local queries such as adjacent faces and incident edges.

  3. It is suitable for rendering, meshing and surface-based operations.

  4. It is the dominant representation in many CAD kernels.

Limitations of B-Rep

  1. Boolean operations are algorithmically difficult.

  2. Topological consistency must be carefully maintained.

  3. Small numerical errors can create gaps, sliver faces or non-manifold edges.

Winged-Edge Data Structure

Learning source: Shene’s “The Winged-Edge Data Structure” [7]. For the original representation, see Baumgart [16], Section II.

The winged-edge data structure is a classical data structure for representing polyhedral boundary models.

Each edge stores references to:

  1. its two endpoint vertices,

  2. its two adjacent faces,

  3. the previous and next edges around each adjacent face.

Thus, an edge is treated as the central entity. The two faces adjacent to the edge are sometimes called its left and right faces.

A typical winged-edge record contains:

\[ \text{Edge}= (v_1,v_2,f_L,f_R,e_{L}^{prev},e_{L}^{next},e_{R}^{prev},e_{R}^{next}). \]

Key Idea

The winged-edge data structure is designed to answer adjacency queries efficiently. For example, it can quickly find the faces adjacent to an edge or the neighboring edges around a face.

Half-Edge Data Structure

Further reading: Mäntylä [14] and the official CGAL halfedge documentation [17]. Implementation conventions may differ from the simplified examples here.

The half-edge data structure is one of the most widely used data structures for polygon meshes and B-Rep topology.

For the selected tetrahedron, cube, or pentagonal prism, use Download half-edges (CSV) in the interactive explorer above to obtain its complete half-edge table.

The main idea is to split each edge into two oppositely oriented half-edges.

If an edge connects vertices \(v_i\) and \(v_j\), then the two half-edges are:

\[ h_{ij}:v_i\rightarrow v_j, \qquad h_{ji}:v_j\rightarrow v_i. \]

Each half-edge stores references to:

  1. its origin vertex,

  2. its twin half-edge,

  3. the next half-edge around the face,

  4. the previous half-edge around the face,

  5. the face to its left.

A typical half-edge record is

\[ h=(\text{origin},\text{twin},\text{next},\text{prev},\text{face}). \]

Key Idea

The half-edge data structure represents orientation explicitly. This makes it very convenient for traversing faces, vertices and neighboring elements.

Basic Queries

The half-edge data structure makes the following queries easy:

  1. find all vertices of a face,

  2. find all edges of a face,

  3. find all faces adjacent to a given face,

  4. find all edges incident on a vertex,

  5. find all neighboring vertices of a vertex,

  6. test whether an edge is on the boundary.

Implementation of Half-Edge Queries in Python

The following Python code shows a minimal half-edge data structure. It is intended for teaching purposes and is not a complete CAD kernel.

from dataclasses import dataclass
from typing import Optional, List


@dataclass
class Vertex:
    id: int
    x: float
    y: float
    z: float
    halfedge: Optional["HalfEdge"] = None


@dataclass
class Face:
    id: int
    halfedge: Optional["HalfEdge"] = None


@dataclass
class HalfEdge:
    id: int
    origin: Vertex
    twin: Optional["HalfEdge"] = None
    next: Optional["HalfEdge"] = None
    prev: Optional["HalfEdge"] = None
    face: Optional[Face] = None

Query: Vertices of a Face

To obtain all vertices of a face, start from one half-edge of the face and repeatedly follow the next pointer until the starting half-edge is reached again.

def vertices_of_face(face: Face) -> List[Vertex]:
    vertices = []
    start = face.halfedge
    h = start

    while True:
        vertices.append(h.origin)
        h = h.next
        if h == start:
            break

    return vertices

Query: Half-Edges of a Face

def halfedges_of_face(face: Face) -> List[HalfEdge]:
    halfedges = []
    start = face.halfedge
    h = start

    while True:
        halfedges.append(h)
        h = h.next
        if h == start:
            break

    return halfedges

Query: Adjacent Faces

A face adjacent to a given face across a half-edge is obtained by crossing the twin half-edge.

def adjacent_faces(face: Face) -> List[Face]:
    neighbors = []

    for h in halfedges_of_face(face):
        if h.twin is not None and h.twin.face is not None:
            neighbors.append(h.twin.face)

    return neighbors

Query: Neighboring Vertices of a Vertex

To find neighboring vertices of a vertex, move around the vertex by repeatedly using the twin and next pointers.

def neighboring_vertices(vertex: Vertex) -> List[Vertex]:
    neighbors = []
    start = vertex.halfedge
    h = start

    while True:
        if h.twin is None:
            break

        neighbors.append(h.twin.origin)
        h = h.twin.next

        if h == start:
            break

    return neighbors

Remark

The above code assumes a consistently oriented manifold mesh. Boundary edges, non-manifold vertices and disconnected components require additional checks.

Constructive Solid Geometry

Constructive Solid Geometry, abbreviated as CSG, represents solids by combining primitive solids using Boolean operations.

Common primitive solids are:

  1. cube,

  2. sphere,

  3. cylinder,

  4. cone,

  5. torus.

The main Boolean operations are:

\[ A\cup B \quad\text{union}, \]
\[ A\cap B \quad\text{intersection}, \]

and

\[ A-B \quad\text{difference}. \]

A CSG model is commonly represented as a tree. The leaves of the tree are primitive solids, and the internal nodes are Boolean operations. This tree is a set-theoretic expression for the solid; it is not the same as a parametric feature-history graph, which may contain many non-Boolean operations and dependency references.

Key Idea

In CSG, a complex solid is built by combining simple primitive solids using Boolean operations.

Example

A block with a cylindrical hole may be represented as

\[ \text{Block with hole} = \text{Cube} - \text{Cylinder}. \]

This representation directly captures the design intention: a cylinder has been removed from a block.

Advantages of CSG

  1. Simple and intuitive construction from primitives.

  2. Compact representation for suitable shapes.

  3. The constructive Boolean expression is retained explicitly and can be reevaluated.

Boolean Operations and Manufacturing

Boolean operations are set-theoretic geometric operations, not manufacturing processes. Difference can resemble idealized material removal, such as drilling a cylindrical hole, and union can sometimes resemble adding or joining material at the shape level. Intersection generally has no direct manufacturing analogue: it simply keeps the volume common to both operands. None of these operations, by itself, specifies tooling, access, sequence, tolerances or process physics.

Limitations of CSG

  1. Rendering and meshing require conversion to boundary representation.

  2. Local surface adjacency information is not directly available.

  3. Complex freeform surfaces are harder to represent directly.

Introduction to OpenSCAD

Language reference: the official OpenSCAD documentation index [18] links to the manual for primitives, transformations and Boolean operations.

OpenSCAD is a script-based solid modeling tool based largely on the CSG philosophy. Instead of interactively dragging features with a mouse, the user writes code to create solids.

A simple cube is created as:

cube([20, 20, 10]);

A sphere is created as:

sphere(r = 10);

A cylinder is created as:

cylinder(h = 30, r = 5);

The following OpenSCAD code creates a block with a cylindrical hole:

difference() {
    cube([40, 30, 20], center = true);

    cylinder(h = 30, r = 6, center = true);
}

Here the difference() operation subtracts the cylinder from the cube.

Key Idea

OpenSCAD is useful for teaching CSG because the modeling operations are explicit in the code. The model is described procedurally rather than interactively.

OpenSCAD also supports transformations:

translate([20, 0, 0])
rotate([0, 0, 45])
cube([10, 10, 10]);

This creates a cube, rotates it about the \(z\)-axis and then translates it.

Remark

OpenSCAD is especially useful for parametric modeling. Dimensions can be stored as variables, and changing a variable automatically changes the generated model.

Creation of Half-Edge Data Structure using Euler Operators

Further reading on Euler operators: Mäntylä [14], Baumgart [16], §III.A, and CGAL’s Euler-operations reference [17].

Euler operators are elementary topological operations used to construct and modify boundary representations while preserving specified topological invariants when their preconditions are satisfied.

Instead of directly editing lists of vertices, edges and faces, a CAD kernel can use Euler operators to maintain controlled incidence changes. This does not, by itself, guarantee complete topological or geometric validity.

Common Euler operators include:

OperatorMeaning
MVFSMake Vertex Face Solid. Creates a new solid with one vertex and one face.
MEVMake Edge Vertex. Creates a new edge and a new vertex from an existing vertex.
MEFMake Edge Face. Creates a new edge between two vertices and splits a face into two faces.
KEVKill Edge Vertex. Deletes an edge and a vertex. It is the inverse of MEV.
KEFKill Edge Face. Deletes an edge and merges two faces. It is the inverse of MEF.
KEMRKill Edge Make Ring. Deletes an edge and creates an inner loop or ring.
MEKRMake Edge Kill Ring. Creates an edge and removes a ring.

Key Idea

Euler operators are topology-preserving construction rules for B-Rep models. They modify the numbers of vertices, edges, faces, loops, shells and genus in a controlled way.

Illustrative Construction of a Face

A simple polygonal face can be created conceptually as follows.

  1. Use MVFS to create an initial solid with one vertex and one face.

  2. Use MEV repeatedly to create additional vertices and edges.

  3. Use MEF to close the polygon and split the face if necessary.

For example, a quadrilateral face may be created by starting with one vertex and adding vertices one by one using MEV. Finally, an edge is added between the last and first vertices to close the loop.

At the half-edge level, each edge creation produces two half-edges:

\[ h_{ij}:v_i\rightarrow v_j, \qquad h_{ji}:v_j\rightarrow v_i. \]

The next and prev pointers are updated so that the boundary of the face forms a closed cycle.

Example

For a face bounded by vertices

\[ v_0,v_1,v_2,v_3, \]

the half-edge loop is

\[ h_{01}\rightarrow h_{12}\rightarrow h_{23}\rightarrow h_{30}\rightarrow h_{01}. \]

The opposite half-edges form twin pairs:

\[ h_{01}\leftrightarrow h_{10}, \quad h_{12}\leftrightarrow h_{21}, \quad h_{23}\leftrightarrow h_{32}, \quad h_{30}\leftrightarrow h_{03}. \]

Uses of Euler Operators

Euler operators are used in solid modeling for several important purposes.

  1. Topology-controlled construction: They provide a systematic way to build B-Rep models while maintaining specified topological invariants.

  2. Editing of topology: They allow edges, faces, holes and loops to be added or removed in a controlled way.

  3. Implementation of CAD kernels: Many solid-modeling kernels use Euler operators internally to manage topological changes.

  4. Consistency checking: Euler-type relations provide necessary checks that can reveal some invalid topology, but passing them is not a validity proof.

  5. Boolean operations: Boolean operations create and remove faces, edges and vertices. Euler operators provide the low-level topological tools needed for such updates.

  6. Mesh generation and repair: Euler operators are useful for splitting, merging and repairing mesh elements.

Key Idea

Euler operators provide the bridge between abstract topology and practical data-structure manipulation in solid modeling.

Summary

Solid modeling is concerned with representing complete three-dimensional objects, not merely their drawings. A valid solid model must clearly distinguish interior, boundary and exterior. B-Rep represents solids through vertices, edges and faces, while CSG represents solids through Boolean combinations of primitives. Feature-based parametric modeling is a higher-level history and dependency graph that typically rebuilds B-Rep bodies; it is not a peer geometric representation.

The distinction between geometry and topology is central to solid modeling. Geometry specifies coordinates, curves and surfaces. Topology specifies adjacency, connectivity and genus. Data structures such as winged-edge and half-edge representations are used to implement topological queries efficiently. Euler characteristic and Euler operators support necessary topological consistency checks and controlled edits; separate topological and geometric tests are still required to establish model validity.
